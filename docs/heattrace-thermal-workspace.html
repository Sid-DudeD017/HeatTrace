HeatTrace · thermal-stress validation sprint

From heatwave label to operational mechanism

A three-day implementation workspace for testing whether temperature-unaware carbon schedulers overcommit when cooling overhead rises and effective compute capacity falls.

Core hypothesis

Static-capacity scheduling may be invalid under thermal stress

The existing benchmark uses temperature to select and label events, but scheduling feasibility is governed by a constant compute-power cap. This sprint introduces a controlled physical pathway from ambient heat to facility operation.

Ambient temperature rises
PUE / cooling overhead rises
Effective compute capacity falls
Unaware scheduler overcommits
Violations, unmet work, regret
Decision ruleTest the hypothesis; do not tune parameters until failure appears. If invalidity occurs only under the high-sensitivity curve, describe it as a controlled stress boundary.

Integration contract

  1. Leave existing P1–P5.5 outputs untouched.
  2. Add temperature and thermal scenario IDs to the experiment context.
  3. Unaware policies receive the nominal static compute cap.
  4. Heat-aware policies receive an hourly capacity vector.
  5. Both are scored against the same realized hourly PUE and facility cap.
  6. Persist schedule digest, thermal config digest and realized score digest.
Failure threshold to freezeA run is operationally invalid if any hour exceeds the facility cap by more than the numerical tolerance, or any required workload remains unfinished by its deadline.

PUE(T), effective capacity and facility energy
src/heattrace/thermal/model.py
from __future__ import annotations

from dataclasses import dataclass
import numpy as np
import pandas as pd


@dataclass(frozen=True)
class ThermalScenario:
    scenario_id: str
    base_pue: float
    threshold_c: float
    slope_per_c: float
    max_pue: float


THERMAL_SCENARIOS = {
    "low": ThermalScenario("low", 1.20, 22.0, 0.010, 1.45),
    "medium": ThermalScenario("medium", 1.20, 22.0, 0.020, 1.70),
    "high": ThermalScenario("high", 1.20, 22.0, 0.035, 2.00),
}


def pue_from_temperature(
    temperature_c: pd.Series | np.ndarray,
    scenario: ThermalScenario,
) -> np.ndarray:
    """Controlled piecewise sensitivity model; not a calibrated facility model."""
    temp = np.asarray(temperature_c, dtype=float)
    if np.isnan(temp).any():
        raise ValueError("temperature contains missing values")
    excess = np.maximum(temp - scenario.threshold_c, 0.0)
    pue = scenario.base_pue + scenario.slope_per_c * excess
    return np.minimum(pue, scenario.max_pue)


def effective_compute_capacity_kw(
    facility_power_cap_kw: float,
    pue: np.ndarray,
) -> np.ndarray:
    if facility_power_cap_kw <= 0 or np.any(pue < 1.0):
        raise ValueError("facility cap must be positive and PUE must be at least 1")
    return facility_power_cap_kw / pue


def facility_energy_kwh(
    compute_energy_kwh: np.ndarray,
    pue: np.ndarray,
) -> np.ndarray:
    compute = np.asarray(compute_energy_kwh, dtype=float)
    if compute.shape != pue.shape:
        raise ValueError("compute energy and PUE must have identical shapes")
    return compute * pue
Thermal violation and cooling-adjusted metrics
src/heattrace/thermal/metrics.py
from __future__ import annotations

import numpy as np


def compute_thermal_metrics(
    compute_power_kw: np.ndarray,
    pue: np.ndarray,
    facility_cap_kw: float,
    price_usd_per_mwh: np.ndarray,
    carbon_g_per_kwh: np.ndarray,
    tolerance_kw: float = 1e-6,
) -> dict[str, float | int | bool]:
    compute = np.asarray(compute_power_kw, dtype=float)
    facility = compute * pue
    excess = np.maximum(facility - facility_cap_kw, 0.0)
    cooling = facility - compute
    violation_mask = excess > tolerance_kw

    cost = facility * np.asarray(price_usd_per_mwh) / 1000.0
    carbon_kg = facility * np.asarray(carbon_g_per_kwh) / 1000.0

    return {
        "facility_energy_kwh": float(facility.sum()),
        "cooling_energy_kwh": float(cooling.sum()),
        "facility_power_violation_hours": int(violation_mask.sum()),
        "max_facility_power_excess_kw": float(excess.max(initial=0.0)),
        "total_facility_power_excess_kwh": float(excess.sum()),
        "cooling_adjusted_cost_usd": float(cost.sum()),
        "cooling_adjusted_carbon_kg": float(carbon_kg.sum()),
        "thermally_feasible": bool(not violation_mask.any()),
    }
Temperature-unaware and heat-aware scheduler adapters
src/heattrace/thermal/scheduler.py
from __future__ import annotations

from dataclasses import replace
import numpy as np
import pandas as pd

from heattrace.policy.interfaces import (
    ForecastResult,
    ScheduleResult,
    SchedulingConstraints,
    SchedulingPolicy,
)


def schedule_temperature_unaware(
    policy: SchedulingPolicy,
    workload_df: pd.DataFrame,
    forecast: ForecastResult,
    nominal_compute_cap_kw: float,
    max_concurrent_jobs: int,
) -> ScheduleResult:
    """Existing baseline: one static compute-capacity assumption."""
    constraints = SchedulingConstraints(
        max_cluster_power_kw=nominal_compute_cap_kw,
        max_concurrent_jobs=max_concurrent_jobs,
    )
    return policy.schedule(workload_df, forecast, constraints)


def schedule_heat_aware_greedy(
    policy: SchedulingPolicy,
    workload_df: pd.DataFrame,
    forecast: ForecastResult,
    effective_capacity_kw: np.ndarray,
    max_concurrent_jobs: int,
) -> ScheduleResult:
    """Adapter: schedule, then repair allocations that exceed hourly capacity.

    Replace with a native hourly-capacity policy after the minimum viable sprint.
    The repair is deterministic and never moves work outside arrival/deadline bounds.
    """
    static_cap = float(np.max(effective_capacity_kw))
    original = policy.schedule(
        workload_df,
        forecast,
        SchedulingConstraints(static_cap, max_concurrent_jobs),
    )

    jobs = workload_df.set_index("job_id")
    hourly_power = np.zeros(len(effective_capacity_kw), dtype=float)
    accepted = []
    deferred = []

    for allocation in sorted(
        original.allocations,
        key=lambda a: (a.allocated_hour_offset, a.job_id),
    ):
        h = allocation.allocated_hour_offset
        if hourly_power[h] + allocation.execution_power_kw <= effective_capacity_kw[h] + 1e-6:
            accepted.append(allocation)
            hourly_power[h] += allocation.execution_power_kw
        else:
            deferred.append(allocation)

    unmet = []
    for allocation in deferred:
        job = jobs.loc[allocation.job_id]
        start = max(int(job.arrival_offset_hours), allocation.allocated_hour_offset + 1)
        stop = min(int(job.deadline_offset_hours), len(effective_capacity_kw) - 1)
        placed = False
        for h in range(start, stop + 1):
            if hourly_power[h] + allocation.execution_power_kw <= effective_capacity_kw[h] + 1e-6:
                accepted.append(replace(allocation, allocated_hour_offset=h))
                hourly_power[h] += allocation.execution_power_kw
                placed = True
                break
        if not placed:
            unmet.append(allocation.job_id)

    return replace(
        original,
        policy_name=f"{original.policy_name}_heat_aware",
        allocations=accepted,
        is_feasible=not unmet,
        unmet_deadlines=sorted(set(unmet)),
    )

from __future__ import annotations

import hashlib
import pandas as pd


def workload_identity_digest(workload_df: pd.DataFrame) -> str:
    cols = [
        "job_id", "arrival_offset_hours", "deadline_offset_hours",
        "processing_requirement", "energy_kwh", "priority",
    ]
    payload = workload_df[cols].sort_values("job_id").to_csv(index=False)
    return hashlib.sha256(payload.encode("utf-8")).hexdigest()


def validate_matched_inputs(
    event_workload: pd.DataFrame,
    control_workload: pd.DataFrame,
    event_window: pd.DataFrame,
    control_window: pd.DataFrame,
) -> None:
    if workload_identity_digest(event_workload) != workload_identity_digest(control_workload):
        raise ValueError("event and control workloads are not identical")
    if len(event_window) != 120 or len(control_window) != 120:
        raise ValueError("both windows must contain exactly 120 hourly rows")
    for frame, name in [(event_window, "event"), (control_window, "control")]:
        if frame["timestamp_utc"].duplicated().any():
            raise ValueError(f"{name} contains duplicate timestamps")
        if frame["temperature_c"].isna().any():
            raise ValueError(f"{name} contains missing temperature")
Experiment runner skeleton
src/heattrace/experiments/p6_thermal_runner.py
from __future__ import annotations

import numpy as np
import pandas as pd

from heattrace.thermal.metrics import compute_thermal_metrics
from heattrace.thermal.model import (
    THERMAL_SCENARIOS,
    effective_compute_capacity_kw,
    pue_from_temperature,
)
from heattrace.thermal.scheduler import (
    schedule_heat_aware_greedy,
    schedule_temperature_unaware,
)


def hourly_compute_power(schedule, horizon: int) -> np.ndarray:
    result = np.zeros(horizon, dtype=float)
    for allocation in schedule.allocations:
        result[allocation.allocated_hour_offset] += allocation.execution_power_kw
    return result


def run_thermal_pair(
    windows: dict[str, pd.DataFrame],
    workload_df: pd.DataFrame,
    policy,
    forecasts: dict[str, object],
    facility_cap_kw: float,
    max_concurrent_jobs: int,
) -> pd.DataFrame:
    rows = []
    for window_id, realized in windows.items():
        for sensitivity, scenario in THERMAL_SCENARIOS.items():
            pue = pue_from_temperature(realized["temperature_c"], scenario)
            effective_cap = effective_compute_capacity_kw(facility_cap_kw, pue)

            schedules = {
                "temperature_unaware": schedule_temperature_unaware(
                    policy, workload_df, forecasts[window_id],
                    nominal_compute_cap_kw=facility_cap_kw / scenario.base_pue,
                    max_concurrent_jobs=max_concurrent_jobs,
                ),
                "heat_aware": schedule_heat_aware_greedy(
                    policy, workload_df, forecasts[window_id], effective_cap,
                    max_concurrent_jobs=max_concurrent_jobs,
                ),
            }

            for policy_class, schedule in schedules.items():
                metrics = compute_thermal_metrics(
                    compute_power_kw=hourly_compute_power(schedule, len(realized)),
                    pue=pue,
                    facility_cap_kw=facility_cap_kw,
                    price_usd_per_mwh=realized["price_usd_per_mwh"].to_numpy(),
                    carbon_g_per_kwh=realized["carbon_g_per_kwh"].to_numpy(),
                )
                rows.append({
                    "window_id": window_id,
                    "window_type": realized["window_type"].iloc[0],
                    "thermal_sensitivity": sensitivity,
                    "policy_class": policy_class,
                    "schedule_feasible": schedule.is_feasible,
                    **metrics,
                })
    return pd.DataFrame(rows)

Limitations template

This prototype evaluates one historical CAISO heatwave and one matched control using a controlled temperature-dependent PUE sensitivity model. The thermal relationship is an experimental intervention rather than a calibrated model of a named data center. Results therefore identify conditional stress boundaries and potential evaluation failures; they do not estimate the prevalence of scheduler failures across facilities, regions or heatwaves. The heat-aware adapter is not a faithful implementation of Ruparel's adaptive DRO algorithm. Carbon outcomes use quality-limited production-average intensity and must not be interpreted as avoided marginal emissions. Multi-event replication, authentic facility telemetry, operational temperature forecasts and independent scheduler implementations are required before making general claims.

Outcome-contingent claim

If violations appear under low/medium sensitivity: “Under the frozen controlled model, static-capacity scheduling produced thermally invalid allocations during the selected heatwave that were absent or materially smaller in the matched control; heat-aware capacity scheduling reduced those violations.”

If only high sensitivity fails: “HeatTrace identifies a thermal-stress boundary beyond which static-capacity scheduling becomes invalid; lower sensitivities primarily reveal facility-energy underestimation.”

If no failures appear: “Schedulers remained feasible in the tested case, but static energy accounting underestimated cooling-adjusted facility energy, cost and carbon during the heatwave.”
